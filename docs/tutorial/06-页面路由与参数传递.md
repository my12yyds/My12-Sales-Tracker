# 06 页面路由与参数传递

> 本章涉及的 API：`wx.navigateTo`、`wx.navigateBack`、`wx.redirectTo`、`wx.reLaunch`

四个跳转 API 名字很像，区别只有一个：**跳过去之后，当前页面怎么处理**。选错的后果是「返回键失灵」或者「页面栈爆掉」。

## 6.1 四个 API 的本质区别

| API | 当前页面 | 新页面 | 页面栈变化 | 典型场景 |
| --- | --- | --- | --- | --- |
| `wx.navigateTo` | 保留 | 压入栈 | +1 | 列表 → 详情 |
| `wx.redirectTo` | **销毁** | 替换当前 | 不变 | 未登录 → 登录页 |
| `wx.reLaunch` | **全部销毁** | 作为唯一页面 | 清空后 +1 | 登录成功 → 首页 |
| `wx.navigateBack` | 销毁自己 | 回上一层 | -1 | 详情 → 返回列表 |

一句话记忆：

- **要能返回上一页** → `navigateTo`
- **不要用户返回到这里** → `redirectTo`
- **要重置整个导航历史** → `reLaunch`

### 还有一个 switchTab

`wx.switchTab` 只能跳 `tabBar` 页面（`app.json` 里配了 `tabBar` 的那几个）。本项目**没有用 tabBar**，所以全部用前四个。如果你的项目有底部导航，跳到 tabBar 页面必须用 `switchTab`，用 `navigateTo` 会直接失败——这是新手很常见的困惑。

## 6.2 navigateTo：最常用的那个

```js
// miniprogram/utils/lead-page.js:124
onLeadTap(e) {
  wx.navigateTo({ url: '/pages/lead-detail/index?leadId=' + encodeURIComponent(e.currentTarget.dataset.id) });
}
```

### 页面栈有上限

小程序页面栈**最多 10 层**。超过之后 `navigateTo` 会失败（不报错，就是没反应）。

什么情况会撞上？典型是「列表 → 详情 → 从详情点某个关联记录 → 又是详情 → ...」这种可以无限深入的路径。本项目的页面跳转都是单向的（列表 → 详情 → 编辑 → 返回），不会累积，所以没做特殊处理。

如果你的业务可能深层嵌套，要么用 `redirectTo` 替换当前页，要么在跳转前判断 `getCurrentPages().length`。

### 路径必须是在 app.json 注册过的

```js
wx.navigateTo({ url: '/pages/lead-detail/index?leadId=abc' });
```

路径以 `/` 开头表示从根目录算。写错一个字、或者忘了在 `app.json` 的 `pages` 里注册，都会静默失败。

**建议**：跳转路径写成常量或集中管理。本项目是分散写的（因为每个页面的跳转目标固定），量小还能接受。

## 6.3 传参：query string，全是字符串

小程序页面传参**只能通过 URL query**，格式和浏览器一样：

```js
'/pages/lead-detail/index?leadId=' + encodeURIComponent(id)
```

接收方在 `onLoad(options)` 里拿：

```js
// miniprogram/pages/lead-detail/index.js:23-31
onLoad(options) {
  const { leadId } = options;
  if (!leadId) {
    wx.showToast({ title: '参数错误', icon: 'none' });
    setTimeout(() => wx.navigateBack(), 1500);
    return;
  }
  this.setData({ leadId });
  this.loadData();
}
```

### 要点一：拿到的永远是字符串

```js
// miniprogram/pages/admin/group-leads/index.js:22-30
onLoad(options) {
  const { groupId } = options;
  if (!groupId) { /* ... */ return; }
  this.setData({ groupId: Number(groupId) });   // ← 必须自己转数字
  this.loadLeads();
}
```

`groupId` 在数据库里是 `Number`，但 `options.groupId` 是 `String`。不转换的话，后面拿它去查库就查不到——这正是[第 04 章](04-查询指令与分页上限.md)提到的「字符串 groupId 静默查不到数据」。

**为什么必须转？** 因为 `where({ groupId: "5" })` 匹配不到数字 `5`。云开发不做类型转换。

### 要点二：中文和特殊字符要 encode

```js
'/pages/lead-detail/index?name=' + encodeURIComponent('张三&李四')
```

不编码的话，名字里的 `&` 会被当成参数分隔符，`?` 会截断后面的内容。`encodeURIComponent` 把 `&`、`=`、`?`、中文都转成安全字符。

对应的，接收方如果要用原始值，需要 `decodeURIComponent`。不过小程序框架在 `options` 里**已经帮你解码过了**，所以本项目的 `leadId`（数据库自动生成的字母数字 ID）不需要额外处理。

**实践建议**：ID 类参数（字母数字）编码与否都安全，但统一加 `encodeURIComponent` 是零成本的好习惯。本项目就是这么做的。

### 要点三：不要用 query 传对象

```js
// ❌ 不要这样
wx.navigateTo({ url: '/pages/detail/index?data=' + JSON.stringify(obj) });
```

两个问题：

1. **长度限制**：URL 有长度上限，对象稍大就超了；
2. **可读性和安全性**：URL 会出现在页面栈里，用户理论上能看到。

需要传复杂数据时的正确做法：

- **只传 ID，目标页面自己去查**（本项目全部采用这种方式，`leadId`、`userId`、`groupId` 都是 ID）；
- 或者用 `getApp().globalData` 中转（注意小程序被回收后会丢）；
- 或者用本地存储中转（见[第 07 章](07-本地存储与登录缓存.md)）。

**「只传 ID 自己查」是最稳的**，因为数据始终以数据库为准，不会出现「页面显示的和数据库不一致」。

## 6.4 redirectTo：不要留下返回路径

```js
// miniprogram/utils/lead-page.js:40
if (!user || user.needRegister) {
  this.setData({ leads: [], total: 0, hasMore: false });
  wx.redirectTo({ url: '/pages/login/index' });
  return;
}
```

这里用的是 `redirectTo` 而不是 `navigateTo`，原因是：**未登录的用户不该能返回到线索列表**。

如果用了 `navigateTo`，页面栈变成 `[列表, 登录]`，用户在登录页按返回，又回到那个空列表，然后再触发一次未登录检查、再跳登录页……形成死循环。

`redirectTo` 把列表页销毁，栈里只剩登录页，返回键直接退出小程序，符合预期。

同样的逻辑出现在 `lead-detail/index.js:44`。

## 6.5 reLaunch：重置导航历史

```js
// miniprogram/pages/login/index.js:21-41（节选）
if (user.needRegister) {
  wx.reLaunch({ url: "/pages/register/index" });
  return;
}
getApp().globalData.user = user;

const role = user.role;
if (role === 1) {
  wx.reLaunch({ url: "/pages/anchor/leads/index" });
} else if (role === 2) {
  wx.reLaunch({ url: "/pages/sales/leads/index" });
} else if (role === 0) {
  wx.reLaunch({ url: "/pages/admin/dashboard/index" });
} else {
  wx.reLaunch({ url: "/pages/home/index" });
}
```

登录成功后用 `reLaunch` 是标准做法，原因：

1. **清空页面栈**：登录页不该留在栈里，否则用户在主页面按返回会回到登录页（已经登录了，很怪）；
2. **不同角色进不同首页**：三种角色对应三个页面，用 `reLaunch` 保证栈里只有一个页面，不会残留上一个角色的页面。

本项目的登录页还有一个细节：**它是启动页**（`app.json` 的 `pages` 第一项）。所以冷启动 → 登录页 → 按角色 `reLaunch` 到目标页，整个流程只有一次入栈，非常干净。

退出登录同理：

```js
// miniprogram/pages/profile/index.js:16
wx.reLaunch({ url: "/pages/login/index" });
```

## 6.6 navigateBack：返回，还能带 delta

```js
// miniprogram/pages/anchor/lead-edit/index.js:232
wx.navigateBack();
```

不带参数默认返回上一页（`delta: 1`）。要一次退多层：

```js
wx.navigateBack({ delta: 2 });   // 连退两层
```

`delta` 超过当前栈深度时会退到第一页，不会报错。

### 一个配套的小技巧：延时返回

本项目里大量出现这个模式：

```js
// miniprogram/pages/lead-detail/index.js:26-27
wx.showToast({ title: '参数错误', icon: 'none' });
setTimeout(() => wx.navigateBack(), 1500);
```

**为什么要 `setTimeout`？** 因为 `showToast` 在页面跳转时会立刻消失（见[第 05 章](05-交互反馈API.md) 5.6）。如果直接 `navigateBack()`，用户根本看不到「参数错误」这四个字，只看到页面闪了一下就退回去了。

延时 1500ms 正好等于 toast 的默认停留时长，让用户看清提示再返回。

**这个 1500 是本项目里出现的魔法数字**，分散在 7 个文件里。如果要重构，可以抽成 `utils/feedback.js` 导出一个 `toastThenBack(title)`。这是个不错的练习。

## 6.7 一个完整的路由设计

把本项目的跳转关系画出来，能看清为什么这样设计：

```
启动 → login（启动页）
        ├─ 未注册 → reLaunch → register → reLaunch → 按角色主页
        └─ 已登录 → reLaunch → 按角色主页
                                  ├─ 负责人 → anchor/leads
                                  ├─ 成员   → sales/leads
                                  └─ 管理员 → admin/dashboard
                                        ↓ navigateTo
                                    lead-detail ← navigateTo ← 列表
                                        ├─ navigateTo → followup-edit → navigateBack
                                        ├─ navigateTo → user-detail   → navigateBack
                                        └─ navigateBack → 列表（onShow 触发刷新）
```

三个设计原则：

1. **登录/注册用 `reLaunch`**，因为它们要重置整个会话状态；
2. **业务页面之间用 `navigateTo`**，保留返回能力；
3. **异常兜底用 `redirectTo`**，避免用户返回到不该回去的页面。

返回列表时靠 `onShow` 自动刷新（[第 01 章](01-项目结构与生命周期.md) 讲过），不需要手动通知，也不需要全局事件总线。这是小程序里最省事的「数据同步」方案。

## 6.8 练习

1. **把 redirectTo 改成 navigateTo**：在 `lead-page.js:40` 改掉，用未登录状态进入列表页，然后按返回，观察死循环。
2. **复现参数类型坑**：把 `group-leads` 里的 `Number(groupId)` 去掉，进入团队线索页，看列表是不是空的。
3. **验证栈深度**：在 `lead-detail` 里加一个「打开自己」的按钮（`navigateTo` 到当前页），连点 11 次，看第 11 次是否失败。
4. **抽公共函数**：把散落的 `setTimeout(() => wx.navigateBack(), 1500)` 抽成 `utils/feedback.js` 里的 `toastThenBack(title)`，替换全部 7 处，跑 `npm test` 确认没破坏。
