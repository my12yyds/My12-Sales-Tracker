# 10 表单组件与选择器

> 本章涉及的组件：`picker`、`input`、`textarea`、`switch`、`radio`、`checkbox`

小程序没有 `<form>` 自动收集表单值的机制（有 `<form>` 组件但要配合 `name` 属性，本项目没用）。所有表单都是**受控组件**：`value` 绑到 `data`，`bindinput`/`bindchange` 把新值写回 `data`。

这一章的重点是**不同组件的 `e.detail.value` 类型完全不一样**，搞错就会出「选了没反应」或者「查不到数据」的问题。

## 10.1 受控组件的基本模式

```html
<input value="{{customerName}}" bindinput="onCustomerNameInput" />
```

```js
onCustomerNameInput(e) { this.setData({ customerName: e.detail.value }); }
```

数据流是一个环：

```
data.customerName  →  value  →  用户输入  →  bindinput  →  e.detail.value  →  setData  →  回到 data
```

**为什么必须写回 `data`？** 因为 `value="{{customerName}}"` 每次渲染都会用 `data` 里的值覆盖输入框。如果 `bindinput` 里不 `setData`，用户输入的字符会被立刻「弹回去」，看起来像输入框坏了。

这是小程序和 React 受控组件一样的约束。如果你只想读值不想同步（比如搜索框），至少也要在某个地方存一下，否则拿不到。

## 10.2 picker：三种模式，三种返回类型

`picker` 是小程序里唯一的选择器组件，通过 `mode` 切换形态。本项目用了两种。

### mode="selector"：从列表里选

```html
<!-- miniprogram/pages/followup-edit/index.wxml:13-19 -->
<picker mode="selector" range="{{statusOptions}}" range-key="label" value="{{statusIndex}}" bindchange="onStatusChange">
  <view class="picker">
    {{statusOptions[statusIndex].label}}
  </view>
</picker>
```

| 属性 | 说明 |
| --- | --- |
| `range` | 数据源。可以是字符串数组（`['A','B']`），也可以是对象数组 |
| `range-key` | `range` 是对象数组时，指定用哪个字段显示 |
| `value` | **当前选中项的下标**（数字），不是值本身 |
| `bindchange` | 用户确认选择后触发 |

**关键点：`value` 是下标，不是选中项的值。**

所以 `data` 里存的是 `statusIndex`（索引），显示时再回数组取：

```html
{{statusOptions[statusIndex].label}}
```

这个设计看起来绕，但好处是「选项列表变了，已选中的位置还有意义」。如果存值本身，选项顺序一变就得做迁移。

`range-key="label"` 的作用：`statusOptions` 是 `[{label: '待处理', value: 'NEW'}, ...]` 这种对象数组，不加 `range-key` 会显示成 `[object Object]`。

### mode="date"：选日期

```html
<!-- miniprogram/pages/followup-edit/index.wxml:6-10 -->
<picker mode="date" value="{{followUpDate}}" bindchange="onDateChange">
  <view class="picker">
    {{followUpDate || '请选择日期'}}
  </view>
</picker>
```

**`value` 是日期字符串 `'YYYY-MM-DD'`**，不是下标，也不是 `Date` 对象。

还支持 `start` / `end` 限制可选范围，本项目用它做「下次跟进不能早于本次跟进」：

```html
<!-- miniprogram/pages/followup-edit/index.wxml:30-32 -->
<picker class="flex-1" mode="date" value="{{nextFollowUpDate}}" start="{{followUpDate}}" bindchange="onNextDateChange">
  <view class="picker">{{nextFollowUpDate || '不设置提醒'}}</view>
</picker>
```

`start="{{followUpDate}}"` 让日期选择器的最小可选值等于本次跟进日期。**这是「UI 层约束」**，但 `onSubmit` 里还做了二次校验：

```js
// miniprogram/pages/followup-edit/index.js:119-122
if (nextFollowUpDate && nextFollowUpDate < followUpDate) {
  wx.showToast({ title: '下次跟进不能早于本次跟进', icon: 'none' });
  return;
}
```

**为什么要校验两次？** 因为 `start` 只是限制选择器能滑到哪，用户完全可以通过别的方式（改 data、构造请求）绕过。前端校验是体验，不是安全。真正的约束要在云函数里再写一遍。

### mode="time" 和 mode="multiSelector"

本项目没用，但列一下便于对照：

| mode | `e.detail.value` 类型 |
| --- | --- |
| `selector` | 下标（**字符串**，如 `"2"`） |
| `multiSelector` | 下标数组（字符串数组） |
| `time` | `'HH:mm'` |
| `date` | `'YYYY-MM-DD'` |
| `region` | 省市区字符串数组 |

## 10.3 e.detail.value 类型总表（重点）

这是本章最该记住的一张表：

| 组件 | `e.detail.value` 类型 | 例子 |
| --- | --- | --- |
| `input` | string | `'13800000001'` |
| `textarea` | string | `'客户说要考虑一下'` |
| `switch` | boolean | `true` |
| `checkbox`（单个） | boolean | `true` |
| `checkbox-group` | string 数组 | `['a', 'c']` |
| `radio-group` | string | `'2'` |
| `picker` mode=selector | **string**（下标） | `'2'` |
| `picker` mode=date | string | `'2026-10-24'` |
| `slider` | number | `50` |

**注意 `picker` 的 selector 模式返回的是字符串 `'2'` 而不是数字 `2`。** 这是最容易踩的坑，下面详细说。

## 10.4 那个「能用但脆弱」的地方

```js
// miniprogram/pages/followup-edit/index.js:73-75
onStatusChange(e) {
  this.setData({ statusIndex: e.detail.value });
},
```

这里没有 `Number()` 转换，`statusIndex` 被存成了字符串 `'2'`。

**能跑吗？能。** 因为后面取选项是这么写的：

```js
// miniprogram/pages/followup-edit/index.js:142
status: statusOptions[statusIndex].value,
```

`statusOptions['2']` 在 JS 里等价于 `statusOptions[2]`——数组的方括号访问会把字符串数字自动转成索引。

**那为什么说脆弱？**

1. 一旦有人写成 `statusIndex + 1`（比如做「下一项」按钮），字符串拼接会得到 `'21'` 而不是 `3`；
2. 一旦有人写成 `statusIndex === 2`，严格相等直接为 `false`；
3. 传给云函数时，字符串 `'2'` 和数字 `2` 在数据库里匹配不到。

对比另一个页面，写法就规范得多：

```js
// miniprogram/utils/lead-page.js:114
onStatusChange(e) { this.setData({ statusIndex: Number(e.detail.value) }); this.loadLeads(); },
```

**统一加 `Number()` 是零成本的好习惯。** 本项目里两种写法并存，属于历史遗留。如果你在自己的项目里写，建议一律转换——或者干脆在 `data` 初始化时就明确类型，转换放在入口。

## 10.5 input：常用属性

```html
<input class="search-input" value="{{keyword}}" maxlength="80"
       placeholder="输入关键词，点击搜索"
       bindinput="onKeywordInput" bindconfirm="onSearch" confirm-type="search" />
```

| 属性 | 作用 |
| --- | --- |
| `value` | 当前值（受控） |
| `placeholder` | 占位文字 |
| `maxlength` | 最大长度，默认 140，`-1` 表示不限 |
| `type` | `text`（默认）/ `number` / `digit` / `idcard` |
| `password` | 是否密码框 |
| `confirm-type` | 键盘右下角按钮文字 |
| `bindinput` | 每次输入触发 |
| `bindfocus` / `bindblur` | 聚焦 / 失焦 |
| `bindconfirm` | 点击键盘确认键 |

**`maxlength` 要和后端校验对齐。** 本项目前端 `maxlength="80"`，云函数 `filters.js:68` 也校验 `keyword.length > 80` 抛错。两边一致，用户不会看到「前端能输、提交报错」的割裂体验。

## 10.6 textarea：注意高度

```html
<textarea class="textarea batch-textarea"
          placeholder="例如：&#10;13800000001&#10;138-0000-0002&#10;13800000003"
          value="{{batchText}}" bindinput="onBatchInput" maxlength="8000" />
```

两个要点：

**`&#10;` 是换行符。** 在 WXML 的 `placeholder` 里不能直接写 `\n`，要用 HTML 实体 `&#10;`。本项目用它演示「一行一个电话」的输入格式。

**textarea 有默认高度，且不支持 `auto-height` 之外的自动撑开。** 加 `auto-height` 可以让它随内容增高：

```html
<textarea auto-height />
```

但 `auto-height` 和固定 `height` 样式冲突，两者选一个。

## 10.7 switch 与 checkbox

```html
<!-- miniprogram/templates/lead-list.wxml:22-23 -->
<view class="row-between"><text>仅看未跟进</text><switch checked="{{unfollowed}}" bindchange="onUnfollowedChange" /></view>
<view class="row-between"><text>记住筛选偏好（不保存关键词）</text><switch checked="{{rememberFilters}}" bindchange="onRememberChange" /></view>
```

```js
onUnfollowedChange(e) { this.setData({ unfollowed: e.detail.value }); this.loadLeads(); },
```

`switch` 的 `e.detail.value` 是 **boolean**，可以直接存。属性名是 `checked` 不是 `value`。

```html
<!-- miniprogram/pages/followup-edit/index.wxml:39-42 -->
<label class="checkbox-label">
  <checkbox checked="{{advanceToNext}}" bindchange="onAdvanceChange" />
  <text>推进到下一个进程</text>
</label>
```

**单个 `checkbox` 的 `bindchange` 返回 boolean**，但多个 checkbox 要用 `checkbox-group` 包起来，返回的是**选中的 value 数组**：

```html
<checkbox-group bindchange="onSalesChange">
  <label wx:for="{{groupSales}}" wx:key="_id">
    <checkbox value="{{item._id}}" checked="{{item.checked}}" />
    <text>{{item.name}}</text>
  </label>
</checkbox-group>
```

```js
onSalesChange(e) { this.setData({ selectedIds: e.detail.value }); }   // ['id1', 'id3']
```

本项目在 `lead-edit` 页里用的是「点一下切换 `checked` 字段」的方式（自己维护数组），而不是 `checkbox-group`。两种都行，`checkbox-group` 更省代码但受控性弱一些。

## 10.8 label 的妙用

```html
<label class="checkbox-label">
  <checkbox checked="{{advanceToNext}}" bindchange="onAdvanceChange" />
  <text>推进到下一个进程</text>
</label>
```

`<label>` 包住的区域内，点击**任何位置**都会触发内部表单组件的默认行为（勾选 checkbox、聚焦 input）。所以不用非得点那个小方块。

这是个纯体验优化，成本一行标签，值得加。

## 10.9 表单校验的分层

看 `onSubmit` 的校验顺序：

```js
// miniprogram/pages/followup-edit/index.js:111-125（节选）
if (!followUpDate) {
  wx.showToast({ title: '请选择跟进日期', icon: 'none' });
  return;
}
if (nextFollowUpDate && nextFollowUpDate < followUpDate) {
  wx.showToast({ title: '下次跟进不能早于本次跟进', icon: 'none' });
  return;
}
if (submitting) return;              // 防重复提交
this.setData({ submitting: true });
```

三层，各有职责：

| 层 | 做什么 | 失败表现 |
| --- | --- | --- |
| UI 层 | `picker` 的 `start` 限制 | 选不到非法日期 |
| 前端校验 | `onSubmit` 里的判断 | toast 提示，不发请求 |
| 云函数校验 | `followUpCreate` 里再查一遍 | 返回 `success: false` |

**为什么三层都要？** 因为：

- UI 限制可以被绕过（改 data、直接构造请求）；
- 前端校验可以被绕过（改客户端代码、用接口工具直接调云函数）；
- 只有云函数是「别人碰不到」的那一层。

所以**云函数里的校验才是真正的校验**，前端那两层是为了体验（少一次网络往返、提示更即时）。

本项目 `followUpCreate` 里还有一个独立的 `validation.js` 模块，专门做日期合法性、状态枚举、备注类型的校验——校验逻辑抽出来，就能单独写测试（`tests/followup-validation.test.js` 就是这么来的）。

## 10.10 练习

1. **复现 picker 的类型坑**：在 `followup-edit` 里加一个按钮，执行 `this.setData({ statusIndex: this.data.statusIndex + 1 })`，连点两次，观察 `statusIndex` 变成什么（提示：`'2' + 1`）。
2. **统一类型转换**：把 `followup-edit` 里所有 `setData({ xxx: e.detail.value })` 的索引类字段都加 `Number()`，跑 `npm test` 确认无副作用。
3. **加一个 radio-group**：把「跟进状态」从 picker 改成 `radio-group`，注意 `e.detail.value` 从「下标字符串」变成「value 字符串」，改动涉及 data 结构、WXML、提交逻辑。
4. **验证 label 的作用**：把 `<label>` 换成 `<view>`，看点击文字还能不能勾选 checkbox。
