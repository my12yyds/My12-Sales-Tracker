# 12 踩坑清单与调试

> 本章是全教程的收口。前面 11 章讲「怎么用」，这一章讲「哪里会翻车」。

下面 10 个坑全部来自这个项目的真实代码和真实 issue，不是假设。每个都给出**错误写法 → 症状 → 修正写法**。

## 12.1 十个坑速查表

| # | 坑 | 症状 | 隐蔽度 |
| --- | --- | --- | --- |
| 1 | 裸 `.get()` 只返回 100 条 | 数据不全，不报错 | ★★★★★ |
| 2 | 空字符串当查询条件 | 第二条起全被判重复 | ★★★★ |
| 3 | 字符串 `groupId` | 静默返回空列表 | ★★★★ |
| 4 | 时间区间写进一个对象 | 只有后一个条件生效 | ★★★★★ |
| 5 | `showToast` 被 `showLoading` 顶掉 | 提示看不见 | ★★★ |
| 6 | toast 遇上页面跳转 | 提示一闪而过 | ★★★ |
| 7 | `e.target` 取 `dataset` | 点文字没反应 | ★★★ |
| 8 | `picker` 返回字符串下标 | 类型错误积累 | ★★★ |
| 9 | 云函数改完没重新部署 | 「我明明改了」 | ★★ |
| 10 | 云函数时区是 UTC | 日期差一天 | ★★★★★ |

隐蔽度越高越危险——不报错的 bug 才是真 bug。

## 12.2 坑 1：裸 .get() 只返回 100 条

**错误写法**（`cloudfunctions/leadCreate/index.js:96-101`）：

```js
const leadsRes = await db.collection('leads')
  .where({ groupId, assignedSalesIds: db.command.in(salesIds) })
  .get();     // 云函数端默认最多 100 条
```

**症状**：统计「每个成员手上有多少线索」时只统计了前 100 条，新线索持续分配给同一个人。不报错、不提示。

**修正**：显式 `limit()` + 分页循环（见[第 04 章](04-查询指令与分页上限.md) 4.4 的 `fetchAll`）。

**怎么提前发现**：写 `.get()` 的时候强制自己回答一句「这条查询最多可能返回多少条」。答不上来就是有问题。

## 12.3 坑 2：空字符串当查询条件

**错误写法**：

```js
const normalizedPhone = phone.trim();          // 可能得到 ''
.where({ groupId, phone: normalizedPhone })    // phone: '' 会命中所有空电话记录
```

**症状**：客户只填名称不填电话时，第一条能创建，第二条起全部提示「本组已存在相同客户电话」。用户完全无法绕过（前端没透出 `force` 选项）。

**为什么必然发生**：创建线索时无条件写入 `phone: normalizedPhone`，所以每条「仅名称」线索在库里都留下 `phone: ''`。空字符串是**有效值**，等值匹配会命中所有同组空电话记录。

**修正**：

```js
// 仅名称、无电话的线索不参与查重
if (event.force !== true && normalizedPhone) {
```

**通用教训**：**把 `''` 和 `null` 当「没有值」处理时，不要直接拿去做等值查询。** 先判断真值，再查。

## 12.4 坑 3：字符串 groupId

**错误写法**（`cloudfunctions/leadList/index.js` 修复前）：

```js
} else if (role === 0) {
  if (event.groupId) {
    query.groupId = event.groupId;   // 前端传 "5" 时匹配不到数字 5
  }
}
```

**症状**：管理员按团队筛选，传 `"5"` 得到空列表。界面显示「该团队没有线索」，管理员以为数据丢了。

**为什么容易发生**：路由 query 参数永远是字符串（[第 06 章](06-页面路由与参数传递.md) 6.3），`picker` 也返回字符串下标（[第 10 章](10-表单组件与选择器.md) 10.3）。字符串悄悄流到数据库层，而数据库不做类型转换。

**修正**：

```js
if (event.groupId) {
  if (!Number.isSafeInteger(event.groupId) || event.groupId < 1) {
    return { success: false, message: '团队筛选无效：需为正整数' };
  }
  query.groupId = event.groupId;
}
```

**通用教训**：**凡是进入数据库查询条件的数字，先校验类型再使用。** 宁可返回明确错误，也不要静默查空。

## 12.5 坑 4：时间区间写进一个对象

**错误写法**：

```js
// 想表达「今天」，结果只剩 lt 生效
{ nextFollowUpAt: db.command.gte(start), nextFollowUpAt: db.command.lt(end) }
```

**症状**：查「今日待跟进」返回了所有日期早于明天的记录，包括上个月的。

**为什么**：JavaScript 对象里同名 key 互相覆盖，最终对象只有 `lt` 一个条件。

**修正**（`cloudfunctions/leadList/filters.js:41-46`）：

```js
conditions.push({ nextFollowUpAt: db.command.gte(start) });
conditions.push({ nextFollowUpAt: db.command.lt(new Date(start.getTime() + DAY_MS)) });
```

拆成两个条件对象，由外层 `db.command.and([...])` 组合。

**通用教训**：**同一字段的多个范围条件，必须拆成多个对象。** 而且这个错误**不会报错**，只能靠测试或对结果。

## 12.6 坑 5：showToast 被 showLoading 顶掉

**错误写法**：

```js
wx.showLoading({ title: '处理中...' });
await doSomething();
wx.showToast({ title: '完成', icon: 'success' });   // 屏幕上还是「处理中...」
```

**症状**：用户只看到转圈，看不到成功提示，以为没成功，又点了一次。

**修正**：`hideLoading()` 必须在 `showToast()` 之前。

```js
await doSomething();
wx.hideLoading();
wx.showToast({ title: '完成', icon: 'success' });
```

**通用教训**：`showToast` 和 `showLoading` 抢同一块原生浮层。这个事实不在参数表里，只能靠经验（或者读[第 05 章](05-交互反馈API.md)）。

## 12.7 坑 6：toast 遇上页面跳转

**错误写法**：

```js
wx.showToast({ title: '参数错误', icon: 'none' });
wx.navigateBack();      // 页面立刻销毁，toast 也跟着没了
```

**症状**：用户只看到页面闪了一下，不知道发生了什么。

**修正**（本项目用了 7 处）：

```js
wx.showToast({ title: '参数错误', icon: 'none' });
setTimeout(() => wx.navigateBack(), 1500);   // 等 toast 显示完再退
```

**通用教训**：**toast 的生命周期绑定在当前页面**。任何「提示 + 跳转」的组合都要考虑顺序。

## 12.8 坑 7：e.target 取 dataset

**错误写法**：

```js
onLeadTap(e) { wx.navigateTo({ url: '...?id=' + e.target.dataset.id }); }
```

**症状**：点卡片边缘能进详情，点卡片中间的文字没反应。

**为什么**：用户点的是内部的 `<text>`，事件冒泡到外层 `<view>`。`e.target` 是 `<text>`（没有 `data-id`），`e.currentTarget` 才是绑事件的 `<view>`。

**修正**：永远用 `e.currentTarget.dataset`。

**通用教训**：**事件对象里 `target` 是「谁被点了」，`currentTarget` 是「谁绑的处理函数」。** 取 dataset 用后者。

## 12.9 坑 8：picker 返回字符串下标

**错误写法**：

```js
onStatusChange(e) { this.setData({ statusIndex: e.detail.value }); }   // 存成 '2'
```

**症状**：当下不会出错（数组的方括号访问会转换），但埋雷：

- `statusIndex + 1` 得到 `'21'` 而不是 `3`；
- `statusIndex === 2` 永远为 `false`；
- 传给云函数时类型不匹配。

**修正**：

```js
onStatusChange(e) { this.setData({ statusIndex: Number(e.detail.value) }); }
```

**通用教训**：**`e.detail.value` 的类型因组件而异**（见[第 10 章](10-表单组件与选择器.md) 10.3 的表）。入口处统一转换，别指望下游兼容。

## 12.10 坑 9：云函数改完没重新部署

**症状**：本地代码改了，云端行为没变。反复检查代码发现「明明是对的」。

**原因**：云函数是独立部署单元。保存文件 ≠ 部署。

**正确流程**：右键云函数目录 → 「上传并部署：云端安装依赖」。

**怎么确认**：在云函数里加一句 `console.log('version-2026-10-24')`，部署后调用一次，去云开发控制台的日志里看有没有新版本标记。

## 12.11 坑 10：云函数时区是 UTC

这是本项目里最隐蔽的一个坑。

**错误写法**：

```js
const today = new Date().toISOString().slice(0, 10);   // UTC 日期
const d = new Date();
const day = d.getDate();                                // UTC 日
```

**症状**：北京时间 0:00~8:00 之间，「今日待跟进」会算成昨天，数据差一天。

**为什么**：云函数运行环境是 UTC。北京时间比 UTC 快 8 小时，所以北京时间早上 7 点时 UTC 还是前一天 23 点。

**修正**（`cloudfunctions/leadList/filters.js:23-28`）：

```js
function chinaToday(now) {
  const timestamp = now === undefined ? Date.now() : now;
  const shifted = new Date(timestamp + 8 * 3600000);   // 手动偏移 8 小时
  if (!Number.isFinite(shifted.getTime())) throw new Error('当前时间无效');
  return shifted.toISOString().slice(0, 10);
}
```

先加 8 小时，再取 ISO 字符串的日期部分。这样不管服务器在哪个时区，结果都是「中国日历日」。

代码注释写得很直白：

```js
// Cloud functions may run in UTC, so local getDate() must not be used here.
```

**通用教训**：**任何涉及「今天/昨天」的逻辑，都必须显式指定时区。** 不要用 `getDate()`、`getMonth()` 这类本地时间方法，它们在云函数里等于 UTC。

## 12.12 调试手段

### 云函数日志

云开发控制台 → 云函数 → 选择函数 → 日志。`console.log` / `console.error` 都在这。

**这是唯一的服务端调试手段。** 没有断点，没有单步，只有日志。所以关键分支要主动打日志：

```js
// cloudfunctions/leadCreate/index.js:152
} catch (error) {
  console.error('创建线索失败:', error);
  return { success: false, message: '创建线索失败：' + error.message };
}
```

`console.error` 和 `console.log` 在日志里是不同级别，方便筛选。

### 本地跑测试验证逻辑

```sh
npm test
```

75 项测试，覆盖了云函数的绝大部分逻辑。**改云函数之前先跑一遍，改完再跑一遍**，能挡住 80% 的低级错误。

测试用 `vm` 沙箱伪造 SDK（[第 11 章](11-权限模型与鉴权链路.md) 11.6），不需要真实云环境。

### 网络面板看不到云函数调用

开发者工具的 Network 面板**不显示 `wx.cloud.callFunction` 的请求**。要看调用详情：

- 云开发控制台 → 云函数 → 日志（看服务端）
- 或者在前端 `console.log(res)` 看返回值

这是很多人第一次用云开发时困惑的地方：以为请求没发出去，其实发了但面板不显示。

### 常见错误码

| 错误码 | 含义 | 处理 |
| --- | --- | --- |
| `-502005` | 集合不存在 | `db.createCollection()` 或控制台手动建 |
| `-501000` | 云函数不存在 | 检查函数名拼写、是否已部署 |
| `-404011` | 云函数执行超时 | 减小批量、调大超时时间 |
| `DATABASE_COLLECTION_NOT_EXIST` | 同上（字符串形式） | 同上 |

本项目对 `-502005` 做了自动处理（`authLogin/index.js:29`、`userRegister/index.js:43`）。

### 真机调试必做

模拟器能跑通不代表真机没问题。至少验证这几项：

- 文件导出（`shareFileMessage` 在模拟器上行为不同）
- 拨号（模拟器直接弹确认，真机才真拨）
- 下拉刷新（模拟器鼠标拖拽和真机手势有差异）
- 时区（如果手机时区不是东八区）

## 12.13 一份自查清单

提交代码前过一遍：

**数据库查询**

- [ ] 每个 `.get()` 都想过「最多返回多少条」了吗？
- [ ] 分页查询加了 `orderBy` 吗？（不加会导致分页顺序不稳定）
- [ ] 同一字段的多个条件拆成多个对象了吗？
- [ ] 进查询条件的数字做过类型校验吗？

**交互**

- [ ] `showLoading` 和 `hideLoading` 成对了吗？
- [ ] `hideLoading` 在 `showToast` 之前吗？
- [ ] 提示 + 跳转的组合有延时吗？

**权限**

- [ ] 身份来自 `getWXContext().OPENID` 吗？
- [ ] 接收了 ID 参数的接口，校验资源归属了吗？
- [ ] 查询条件带 `groupId` 了吗？

**时间**

- [ ] 涉及「今天」的地方用了中国时区吗？
- [ ] 日期字符串格式统一 `YYYY-MM-DD` 吗？

**部署**

- [ ] 云函数重新上传了吗？
- [ ] `npm test` 通过了吗？
- [ ] `npm run check:public` 通过了吗？（防止把真实 AppID/环境 ID 提交上去）
